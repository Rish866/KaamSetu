# KaamSetu v1.4.0 (release candidate, not yet released)

This file becomes the GitHub release notes only after the website is deployed and verified against production. Until then nothing below is live.

## What the release contains
* Candidate: job search with filters and sorting, saved jobs, job detail with explainable match score, apply/withdraw, application timeline, interview responses, invitations, notifications, full profile, resume upload (switched off at release; quarantined until scanned once enabled), consent controls, data export, deletion request, password change with current-password check.
* Employer: company workspace and verification, company profile, team roles, job lifecycle with moderation holds, applicant pipeline, interviews, offers, rejections with reasons, consent-gated contact details, resume access for applicants, candidate discovery with quotas.
* Administrator: role-based console for verification, moderation, reports, users, privacy, audit, email and resume queues, roles and matching weights.
* Database migrations 202611200001–0006 (0006: admin-controlled resume-upload switch, 24-hour scan timeout, `platform_flags()`), Edge Function `unsubscribe`, and the GitHub "Background workers" (ClamAV scanning, parsing, account clean-up, email).
* Maintenance screen: sign-in and dashboards show "KaamSetu is being updated" while the database is older than the website.

## Known limitations at release
* **Email is not delivered** until an email provider and verified domain are configured; messages queue and are visible to admins.
* **Resume uploads are switched off** until an admin enables them after a verified production ClamAV scan. Once on, a file not scanned within 24 hours fails with a visible message instead of staying quarantined.
* Team invitations cannot be accepted while email confirmation is off.
* Mobile-number sign-up: verified in production on the v1.3.0 database (run 44818660584, phone auto-confirm, no SMS sent). The sign-up screen hides the phone option automatically if the project disables phone sign-in.
* Job and applicant pages moved to `/candidate/job?id=…` and `/employer/job?id=…` (static-host safe deep links).
* Account deletion's auth-identity and file clean-up runs in the background worker: CI tested on a local Supabase stack, not yet run in production.
* Legal texts are drafts pending review by a qualified Indian lawyer.
* Android/iOS: test APK and Simulator build only; no signed store builds.

## Upgrade note
v1.3.0 test APKs cannot apply or post jobs after the database migration (the direct table writes they used were security holes). Install the v1.4.0 build.
