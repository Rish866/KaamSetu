# KaamSetu v1.4.0 (release candidate, not yet released)

This file becomes the GitHub release notes only after the website is deployed and verified against production. Until then nothing below is live.

## What the release contains
* Candidate: job search with filters and sorting, saved jobs, job detail with explainable match score, apply/withdraw, application timeline, interview responses, invitations, notifications, full profile, resume upload (quarantined until scanned), consent controls, data export, deletion request, password change with current-password check.
* Employer: company workspace and verification, company profile, team roles, job lifecycle with moderation holds, applicant pipeline, interviews, offers, rejections with reasons, consent-gated contact details, resume access for applicants, candidate discovery with quotas.
* Administrator: role-based console for verification, moderation, reports, users, privacy, audit, email and resume queues, roles and matching weights.
* Database migrations 202611200001–0005 and Edge Functions email-worker, unsubscribe, resume-processor, privacy-worker.

## Known limitations at release
* **Email is not delivered** until an email provider and verified domain are configured; messages queue and are visible to admins.
* **Resumes stay quarantined** (not downloadable by anyone) until a malware scanner is connected; parsing therefore does not run.
* Team invitations cannot be accepted while email confirmation is off.
* Mobile-number sign-up works on the local test stack; in production it depends on the project's SMS provider setting and has not been verified.
* Job and applicant pages moved to `/candidate/job?id=…` and `/employer/job?id=…` (static-host safe deep links).
* Account deletion's auth-identity and file clean-up runs in the privacy worker, which has not been run against real Supabase.
* Legal texts are drafts pending review by a qualified Indian lawyer.
* Android/iOS: test APK and Simulator build only; no signed store builds.

## Upgrade note
v1.3.0 test APKs cannot apply or post jobs after the database migration (the direct table writes they used were security holes). Install the v1.4.0 build.
